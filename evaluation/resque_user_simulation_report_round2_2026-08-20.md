# 輔仁大學課程推薦系統：第二次 ResQue 使用者中心模擬評估與前後比較

評估日期：2026-08-20  
系統版本：115-1 MVP 1.0（本機 127.0.0.1:8080，目前工作樹版本）  
比較基準：第一次 ResQue 模擬評估報告 resque_user_simulation_report_2026-08-20.md  
評估性質：由同一測試者模擬多種學生角色、實際操作目前版本所得的形成性評估；不是對真實學生施測的統計研究。

## 一、評估目的與比較原則

本次評估有兩個目的：

1. 依 Pu、Chen 與 Hu 提出的 ResQue 使用者中心架構，重新評估目前版本的推薦品質、介面與互動、使用者信念、態度及行為意圖。
2. 將目前版本與第一次評估的基準分數比較，確認近期加入的課程群組、硬條件篩選、查詢限制文字處理、課表及系所選擇器等功能，是否實際改善使用者體驗。

第一次報告的分數代表當時實際操作所得的基準。該報告後來在改善建議中追加了部分「實作狀態」說明，但原始角色結果及 ResQue 分數並未因此重算。因此，本報告以前一次原始分數作為比較基準，再以目前正在執行的版本重新操作及評分，避免把「已完成程式修改」誤當成「已完成第二次使用者評估」。

## 二、評估方法

### 2.1 ResQue 構面

本次沿用第一次評估的教育情境改寫，將原架構中的 purchase intention 改為「實際加選／修課意圖」。十五個構面分為四層：

1. 感知品質：推薦準確性、新穎性、多樣性、介面適切性、解釋品質、資訊充分性、互動適切性。
2. 使用者信念：易用性、控制感、透明度、感知有用性。
3. 使用者態度：整體滿意度、信心與信任。
4. 行為意圖：持續使用意圖、實際加選／修課意圖。

評分採 1–5 分：5＝幾乎所有情境都符合，4＝多數符合，3＝表現混合，2＝經常失敗，1＝嚴重失敗。分數是依實際操作證據所做的專家模擬評分，不是假裝成真實學生填答的問卷資料。

### 2.2 模擬角色與任務範圍

第二次評估重新操作下列身分與情境：

- 日間部大學部：資訊工程、圖書資訊、心理、企業管理、新聞傳播、財經法律、食品科學、護理。
- 研究所：資訊工程碩士班、心理學博士班。
- 特殊修課身分：進修部在職學生、學士後護理學生、需要全英語授課的國際學生情境。
- 裝置與操作限制：僅能週六上課、390×844 手機畫面、未先輸入已修課紀錄、切換學生身分後沿用舊篩選。

測試涵蓋初次設定、系所搜尋、自然語言推薦、星期／時段／學分／學制／程度／先修篩選、跨系設定、課程群組、查看課綱、收藏、不感興趣、加入課表、衝堂排除、AI 小幫手同意流程及手機版面。

### 2.3 解讀限制

本次是單一測試者依角色腳本進行的形成性評估。角色分數可用來比較版本、發現可用性缺陷及安排開發優先級，但不能推論所有輔大學生的滿意度，也不能用來驗證 ResQue 的量表結構或因果模型。

## 七、功能與可靠性補充證據

- 使用「只要博士班」及「排除入門」後，心理博士結果不再包含大學部入門課，學制及程度硬條件生效。
- 進修部選擇「平日晚間＋星期六不限時段」後，前五門課全部在 E 節或符合設定；只勾星期六時，時間未定課程不會混入主要結果。
- 「食品分析實驗」的兩個班別合併成同一卡片，「生物化學實驗」也完成群組，課程多樣性明顯提高。
- 對第一名按「不感興趣」後重新推薦，該課不再出現，負向回饋閉環正常。
- 將課程加入「我的課表」後，該課會從推薦中排除，課表頁正確顯示星期、節次、教師與教室，衝堂排除流程正常。
- 使用者輸入「不要高階先修、只能星期二晚上」時，系統顯示兩段限制文字未送入主題向量；此設計避免否定詞污染語意排名，但限制仍須由使用者手動套用。
- 切換角色時，前一角色的星期六篩選會繼續保留。若使用者沒有注意，可能誤以為新角色只有極少數或不相關課程。
- 搜尋「護理學系」時同時出現「學士後護理學系」及「護理學系」，前者排列在前；搜尋資工研究所時，在職專班排列在一般碩士班前。系所身分仍可能因選錯第一項而失真。
- 全英語需求沒有可靠授課語言欄位或硬篩選，結果只能證明文字相關，不能證明實際以英語授課。
- AI 小幫手的資料傳送範圍說明清楚，但未設定 API key 時，使用者仍須先同意才看到功能不可用。
- 390×844 手機畫面中，主表單仍可操作，但導覽與個人資料按鈕橫向溢出，硬篩選器也過長。

前端測試從 53 筆增加至 77 筆，顯示新增的課程群組、時段、固定課表、查詢文字處理及系所選擇等功能已有更多回歸測試保護。相關性基準分數沒有變化並不與 ResQue 分數上升矛盾：本次改善主要發生在候選硬篩選、多樣性、透明度與互動，而現有 32 筆基準主要衡量一般主題的 Top-10 相關性。

內建基準仍有明顯缺口，例如「想用 Python 處理圖書館資料與資訊分析」Recall@10 及 NDCG@10 均為 0；臺灣歷史、創業創新等查詢也偏低。未來應加入研究所方法課、學制、時段、先修、授課語言及本系親和度等使用者中心案例，不能只以整體 Recall／NDCG 判斷系統是否適合選課。

## 九、第二次評估後的改善建議與優先級

### P0：先處理會造成錯誤身分或嚴重主題錯配的問題

1. **精確系所名稱應優先於部分符合。** 「護理學系」不應由「學士後護理學系」排在第一，「資訊工程學系碩士班」也不應被在職專班遮蔽。建議依完全名稱、學制、部別及代碼排序，並在儲存前再次確認「一般／在職、日間／進修、學士後／一般大學部」。

2. **建立研究所與博士班專用的領域＋方法交集排名。** 心理博士的「多變量、因果推論、研究設計」及資工碩士的「NLP、機器學習」應同時符合學科領域與研究方法，不能只因課名有「研究、博士、論文」就取得高名次。

3. **讓學生檔案真正參與排序，而不只用於分類與資格。** 建議 Top-5 至少保留 2–3 門本系高度相關課，再配置 1–2 門跨域探索課；本系沒有合適課程時才擴大跨系比例，並明示「本系無更相關結果」。

### P1：提升控制感、易用性與實際可修性

4. **切換學生身分時詢問是否重設篩選。** 顯示目前生效中的星期、時段、學制、程度及先修標籤，避免舊角色的星期六或晚間條件靜默影響新角色。

5. **將自然語言限制轉成可一鍵確認的硬篩選。** 當系統辨識「不要高階先修、星期二晚上」時，提供「套用：排除未滿足先修、星期二、晚間 E 節」按鈕，而不只是告知已忽略。

6. **補入授課語言、即時名額及外系開放狀態。** 若無法直接串接校務系統，至少應區分已確認、推測與資料不足，並提供一鍵前往官方核對的清單。

7. **改善手機導覽與長篩選器。** 手機版改用漢堡選單或底部導覽，硬篩選器改為可折疊區段，固定顯示已套用條件數與產生推薦按鈕。

### P2：提升比較效率與長期評估能力

8. **讓推薦理由說明排名貢獻。** 除了「語意與關鍵字命中」，應說明本系／跨系、符合哪個需求、哪些條件無法驗證及為何排在目前名次。

9. **增加候選課程並排比較。** 支援 2–4 門課比較時間、學分、先修、資格、授課語言、推薦理由及待確認事項。

10. **在同意資料傳送前顯示 AI 功能狀態。** 未設定 API key 時直接標示尚未啟用，避免使用者完成隱私判斷後才發現無法使用。

11. **擴充分層評估資料集。** 除一般主題查詢外，加入大學部／碩士／博士、日間／進修、基礎／進階、本系／跨系、時段、先修、否定語意及全英語等案例，分別報告 Top-5 相關且可修比例、重複率與硬條件誤判率。

## 十、建議的下一輪真實學生研究

第二次模擬顯示系統已具備進入真實學生形成性測試的條件。建議先招募 30–50 位學生，分層涵蓋日間部、進修部、一般碩士、在職專班、博士班、學士後、國際學生、跨域修課者及行動裝置使用者。

每位學生完成兩項任務後填寫 ResQue 32 題，並同時記錄：

- 任務成功率。
- 找到第一門可接受課程所需時間。
- Top-5 主題相關且實際可修比例。
- 本系課與跨系課的接受比例。
- 重複課程家族比例。
- 硬條件誤判率與時間未定漏網率。
- 系所／學制設定錯誤率。
- 收藏、加入課表、實際加選與學期後滿意度。

建議發布門檻維持為：關鍵硬限制誤判率 < 2%、Top-5 可修且相關比例 ≥ 80%、重複率 < 10%、任務成功率 ≥ 90%，且 ResQue 的推薦準確性、信任、感知有用性及持續使用意圖平均皆 ≥ 4.0。若要驗證 ResQue 量表結構或進行結構方程模型分析，樣本仍應擴大至約 150–200 人以上。

## 十一、結論

第二次評估顯示，系統整體分數由 3.5 提升至 3.9。最顯著的進步是課程多樣性、硬條件控制、透明度與信任：同課不同班不再占滿前五、進修部時段與博士學制可以可靠限制候選、否定或時間文字不再靜默污染語意向量，課表及回饋閉環也保持正常。

目前最有競爭力的部分是「來源可追溯的跨域探索、結構化安全篩選、課程群組、課表衝堂與本機資料互動」。下一個主要瓶頸已不是單純的畫面或硬條件，而是「如何在正確候選集合內，依學生的系所、學制、程度與細緻學術需求排出真正適合的前五名」。

若優先完成精確身分選擇、研究所領域＋方法交集排名、本系親和度，以及自然語言限制的一鍵套用，最有機會讓推薦準確性、易用性、信任及實際加選意圖進一步跨過 4.0。
