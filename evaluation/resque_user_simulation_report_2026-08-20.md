# 輔仁大學課程推薦系統：ResQue 使用者中心模擬評估

評估日期：2026-08-20  
系統版本：115-1 MVP 1.0（本機 `localhost:8080`）  
評估性質：由測試者模擬多角色、實際操作介面所得的形成性評估；不是對真實學生施測的統計研究。

## 一、評估方法

本次依據 Pu、Chen 與 Hu 的 ResQue 使用者中心架構，將「purchase intention」依教育情境改寫為「實際加選／修課意圖」。15 個構面依原架構分成四層：

1. 感知品質：推薦準確性、新穎性、多樣性、介面適切性、解釋品質、資訊充分性、互動適切性。
2. 使用者信念：易用性、控制感、透明度、感知有用性。
3. 使用者態度：整體滿意度、信心與信任。
4. 行為意圖：持續使用意圖、實際加選／修課意圖。

評分採 1–5 分：5＝幾乎所有情境都符合，4＝多數符合，3＝表現混合，2＝經常失敗，1＝嚴重失敗。分數是依實際操作證據所做的專家模擬評分，不是假裝成真實學生問卷資料。

測試涵蓋：初次設定、自然語言推薦、星期／學分／類別篩選、跨系設定、擋修與資格提示、查看課綱與官方來源、收藏／不感興趣／標記已修、加入課表、衝堂排除、探索搜尋、AI 小幫手、桌面與 390×844 手機版面。

## 四、功能與可靠性補充證據

- 課程庫顯示 4,233 門；探索「人工智慧」得到 32 門，基本搜尋、分頁及資格標示可用。
- 加入「行銷管理（週六 D2–D4）」後，原推薦中與其衝堂的「民商事件法律運用實例演練（週六 D3–D4）」立即消失，衝堂排除有效。
- 對首名課按「不感興趣」後重新推薦，該課維持排除，負向回饋閉環有效。
- 星期六篩選仍會放行「星期未定／節次未定」課程，且沒有明確提示這是例外；對有硬時段限制者風險高。
- AI 小幫手有清楚的資料傳送同意頁，但目前未設定 API key，使用者同意後才看到功能不可用。
- 390×844 手機版主要表單可操作，但頂部導覽與個人資料按鈕橫向超出可視區，功能可發現性不足。
- 在另一個既有來源 `127.0.0.1:8080` 上，舊 IndexedDB 版本為 2，而程式固定要求版本 1，整個課程資料初始化失敗；這是升降版相容性缺陷，可能讓既有使用者無法進站。
- 自動驗證結果：後端 30/30 測試通過、前端 53/53 測試通過、production build 成功。
- 專案內建 32 查詢相關性基準：Recall@10＝0.7219、NDCG@10＝0.6968，通過 0.70／0.60 門檻。它主要衡量主題相關性，不涵蓋否定語意、個人學制、先修或晚間時段，因此與本次使用者中心結果並不矛盾。

## 五、改善建議與優先級

### P0：先處理會造成錯誤決策或無法使用的問題

1. **心理博士二年級、進修部大三與學士後護理大一遇到「文字中明明有學制、時段或先修限制，但系統仍只依整句相似度排序」的問題，因此要用「結構化硬限制」方式改善。** 推薦前先將查詢解析成「想學主題、排除主題、學制、年級、可上星期、可上節次、先修容忍度」，再用這些欄位篩選候選課程。在結果頁逐條顯示「已套用／無法理解／資料不足」，避免使用者以為所有條件都已生效。

2. **心理博士二年級輸入「避免大學入門課」後，前五名卻全部是大學入門；學士後護理大一輸入「不要高階護理先修」後，仍收到內外科與兒科護理，因此要用「否定語意拆分＋排除向量／規則」方式改善。** 現有程式已包含 deterministic compound-query 層，但目前 feature flag 關閉。應預設啟用並強化這一層，且建立兩個必要回歸測試：`避免大學入門課` 必須排除大學入門，`不要高階先修` 必須降排或隱藏需要先修者。

3. **資工大一、企管大二與資工碩一雖然已填寫系所與學制，前五名仍主要由外系課或泛用課占據，因此要用「個人檔案參與分層排名」方式改善。** 學制、系所、年級、進修部與已修課不應只用於標示類別或事後資格判斷，而應直接影響候選與排序。建議採「符合學制／年級 → 本系學程路徑 → 主題相關性 → 新穎跨域」的分層排名，同時保留少量跨域探索名額。

4. **曾經使用 `127.0.0.1:8080` 的既有使用者遇到 IndexedDB 已是版本 2、程式卻固定要求版本 1，導致課程資料完全無法初始化，因此要用「向前資料庫遷移與錯誤復原」方式改善。** 程式不可用低於既有資料庫的固定版本開啟；應加入版本偵測、逐版 migration、失敗時的備份／復原提示與個人資料匯出選項，並建立 v1→v2→新版本的回歸測試。

### P1：直接提升準確性、多樣性、控制感與信任

5. **白天工作的進修部大三要求「只能平日晚間或星期六」，前五名卻有四門白天課；切成星期六後，又出現「星期未定」課程，因此要用「日夜間節次硬篩選＋未知時間獨立處理」方式改善。** 介面應提供「日間 D、晚間 E、週六、指定 D/E 節次」選項，並讓進修生預設偏好晚間。時間未定的課程應預設排除，或集中在「時間待確認」區，不應靜默通過星期篩選。

6. **食科大二的前五名有兩組同課不同班，護理大四重複出現護理研究，資工碩一與財經法律大四也遇到相同內容由不同學制／單位重複開課，因此要用「課程群組化＋多樣性重排序」方式改善。** 可依課名、教師、課程內容、時間與跨開課單位辨識同一教學活動，在一張卡片內呈現可選班別，再使用 MMR 或類別配額避免前五名被近似課程占滿。

   **實作狀態（2026-08-20）：已完成。** 推薦器現在會先依正規化課名、學分、教師、系所、課綱內容與語意向量辨識課程家族；一般同系同名課程會合併，但「專題、論文、獨立研究、個別研究、書報討論、實習」等可能因教師而有不同內容的泛稱課程，仍採保守判斷。群組代表課優先選擇資格較明確、符合學生本系的班別，其餘班別與共同開課項目可在同一卡片展開切換。群組後使用 MMR（預設 λ＝0.78）兼顧相關性與結果間差異，並讓「不感興趣」一次排除整個課程家族。實際以食品科學系二年級情境驗證後，「食品分析實驗」週一／週二班合併為一張卡，原本分列第 6、8 名的醫學系「生物化學實驗」也合併為一張卡；切換後教師、時間、資格、收藏、已修與加入課表的目標會同步改為所選班別。

7. **學士後護理大一明確表示沒有護理背景，系統仍把需要多門先修的內外科護理排在第二名；護理大四未先登錄已修課時，多門合理課程又被標成擋修，因此要用「先修狀態確認＋資格優先排序」方式改善。** 對明確不符學制或年級者直接排除；對未登錄已修課者先詢問，或提供「我已修過／正在修」快速操作。當使用者表示零背景時，應先排列無先修的基礎課，再把高階課放入「未來可修」區。

8. **所有首次設定角色都必須在數百個選項中尋找系所，而且清單包含重複代碼與「資工系入門／人哲／專倫」等非正式系所項，因此要用「分組式可搜尋系所選擇器」方式改善。** 應依日間部／進修部／研究所、學院、正式系所／學位學程／學分學程分組，支援關鍵字與系所代碼搜尋，並在資料層去除重複標籤與不應作為學生身分的開課單位。

9. **進修部大三加入「行銷管理」後，與它衝堂的法律課從推薦中消失，但畫面沒有告訴使用者消失原因；心理博士二年級也看不到「避免大學入門」其實未被正確理解，因此要用「條件對照式解釋」方式改善。** 每張卡應明示符合哪些需求、違反或無法驗證哪些需求、為何排名第 N、屬於本系或跨系，以及是否因衝堂被排除；另提供可查看的排除紀錄與查詢解析摘要。

### P2：提升完成選課的效益與長期評估能力

10. **資工大一、食科大二等角色必須逐張閱讀 20 張長卡片，且重複或待確認課程會增加比較成本，因此要用「結果分區摘要＋候選課程並排比較」方式改善。** 可先把結果濃縮成「最佳符合、可探索、需確認」三區，再讓使用者選取 2–4 門課並排比較學分、時間、先修、資格、推薦理由及尚未符合的條件。

11. **新聞系大三看到多門標示不開放外選的課，財經法律與其他跨系角色則常遇到「尚未判定出明確限制」；所有角色也都無法確認即時名額，因此要用「校務資訊串接或一鍵核對」方式改善。** 若無法直接取得名額與開放狀態，至少在每張卡提供官方核對清單與深層連結，並以更保守的文案區分「已證實可修」、「未發現限制」與「資料不足，必須確認」。

12. **嘗試使用 AI 小幫手的進修部角色先閱讀並同意資料傳送，進入功能後才看到 API key 尚未設定，因此要用「功能狀態前置揭露」方式改善。** 未設定 API key 時，應在導覽直接標示「尚未啟用」、停用入口或在同意前顯示不可用原因，避免使用者完成隱私判斷後才發現功能不能使用。

13. **本次 12 個角色完成收藏、加入課表或排除課程後，系統仍無法知道使用者最後是否真的加選、修完或滿意，因此要用「經同意的學期後成效回饋」方式改善。** 可記錄「看過 → 收藏 → 加入課表 → 實際加選 → 修完滿意」的匿名或去識別化事件，並讓使用者主動確認結果，才能把 ResQue 的滿意度、信任與行為意圖連到真實選課成果。

## 六、建議的下一輪真實學生研究

本次模擬可用來找問題，不能取代真實學生。建議下一輪招募至少 30–50 位做描述性可用性試驗，分層涵蓋日間部、進修部、碩博士班、學士後、跨域修課者與身心障礙／行動裝置使用者；每人完成 2 個任務後填 ResQue 32 題的 5 點量表，並記錄任務成功率、首個可接受課程時間、Top-5 可修且相關比例、重複率、衝堂漏網率與條件誤解率。若要驗證量表結構或做 SEM，樣本應擴大到約 150–200 以上，而非以本次 12 個模擬角色推論母體。

建議預先設定發布門檻：關鍵硬限制誤判率 < 2%、Top-5 可修且相關比例 ≥ 80%、重複率 < 10%、任務成功率 ≥ 90%，且 ResQue 的準確性、信任、有用性與使用意圖平均皆 ≥ 4.0。

## 七、結論

這個系統目前最有競爭力的部分是「跨域課程探索、來源可追溯的解釋、課表衝堂與本機資料互動」。真正限制整體評價的不是畫面，而是**自然語言條件尚未成為可靠的個人化約束**。先完成否定語意、學制／年級／先修、晚間節次與去重，再做介面精修，最能同步拉高 ResQue 的準確性、控制感、信任、滿意度與實際加選意圖。
